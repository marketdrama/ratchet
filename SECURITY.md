# Security

This project is a release candidate and has not received an independent security audit. Do not treat
public source, passing tests or reproducible build evidence as a security certification.

Do not put private keys, authenticated RPC URLs or detailed exploit steps affecting live funds in a
public issue. Use the repository's private vulnerability-reporting feature if enabled. If no private
channel is available, open a minimal issue asking the maintainer for one without disclosing the exploit.
No private reporting channel or response SLA is claimed until the hosting repository is configured.

The current review scope and trust boundaries are in AUDIT_SCOPE.md. Production initialization and
program upgrades require separately secured signers. Retained upgrade authority is intentional for the
temporary showcase; it can change the code and must not be described as immutable.
